# Руководство разработчика ForgeMind

Для разработчиков, которые хотят расширять ForgeMind: как собирать, отлаживать, добавлять новые MCP-инструменты, добавлять адаптеры движков и запускать тесты. Документ основан на реальном коде **публичного среза** (`OpenSource\`, `UEProject\`, `tests\`).

## 1. Обзор проекта

| Проект | Назначение |
|---|---|
| `OpenSource\ForgeMindServer` | Хост MCP-сервера: встроенные 4 инструмента, запуск TCP bridge, загрузка плагинов |
| `OpenSource\ForgeMind.OfflineEngineKit` | Плагин: инструменты engine / project / project_files / switch_version / launch / build / editor |
| `OpenSource\ForgeMind.Assets` | Плагин: инструмент asset (офлайн-чтение `.uasset`) |
| `OpenSource\ForgeMind.Knowledge` | Плагин: инструмент knowledge (поиск по базе знаний) |
| `OpenSource\ForgeMind.EngineScanner` | Сканер командной строки: перечисляет движки и упаковывает `.spk` |
| `OpenSource\ForgeMind.Scan` / `.Scan.Abstractions` / `.Scan.Unreal` | Индекс сканирования: абстракция, упаковка, реализация UE (DocumentEngine) |
| `OpenSource\ForgeMind.Speedy` | Формат упаковки SPK (высокопроизводительный файл пакета) |
| `tests\ForgeMind.PublicTests` | Публичные модульные тесты (без зависимости от движка) |
| `tests\ForgeMindServerTest` | Интеграционные тесты сервера (требуется редактор UE) |
| `UEProject\ForgeMind_5_0` | Пример проекта UE (5.0–5.8) |

## 2. Сборка

```powershell
dotnet build OpenSource\ForgeMindServer\ForgeMindServer.csproj
# Проекты плагинов и библиотек: см. contributing.md §3 (не собирать напрямую весь ForgeMind.sln — содержит ссылки на коммерческие проекты)
```

- Точка входа хоста: `OpenSource\ForgeMindServer\Program.cs` (по умолчанию HTTP слушает `127.0.0.1:8765`, переключение на `--stdio`, переопределение порта через `--port` / `FORGEMIND_PORT`).
- Логи: `LogManager`; инструменты возвращают `ToolResult` (успех / ошибка с сообщением).

## 3. Механизм плагинов и новые MCP-инструменты

В хост встроены только 4 инструмента: `settings`, `get_task_result`, `list_executing_tasks`, `cleanup_tasks`. Остальные инструменты предоставляют **плагины из каталога plugins**:

- Каталог плагинов: `<каталог_хоста>\plugins\` (переопределяется переменной окружения `FORGEMIND_PLUGINS_DIR`).
- Структура пакета плагина: внутри `plugins\<имя_плагина>\` лежат основная DLL, одноимённый `.manifest.json` и зависимости; также поддерживаются свободные DLL в корневом каталоге (ручной drop-in).
- `PluginLoader` хоста сканирует плагины → внедрение `PluginContext` (таблица инструментов, реестр движков, bridge) → плагин вызывает `RegisterTool` в `OnLoad` для регистрации инструментов.
- Целостность плагинов: `PluginIntegrityVerifier` / `PluginSigningKeys` проверяют манифесты и подписи; доверенные плагины могут расширять сервисы через ServiceOverride (см. §7).

Чтобы добавить новый MCP-инструмент:

1. Реализуйте контракт `ITool` (`OpenSource\ForgeMindServer\Compat\ITool.cs`):
   - `Name` / `DisplayName`: имя и отображаемое имя инструмента;
   - `Description`: описание для AI-клиентов;
   - `GetParameterSchema()`: объявление параметров в стиле JSON Schema;
   - `Execute(Guid callerId, Dictionary<string, object> parameters)`: возвращает `ToolResult`.
2. Создайте новый проект плагина (или добавьте в существующий, например OfflineEngineKit), реализуйте `IPlugin` и вызовите `RegisterTool` в `OnLoad`.
3. Положите в тот же каталог одноимённый `.manifest.json` (описание плагина / объявление зависимостей).
4. Для функций на стороне движка отправляйте команды через bridge и реализуйте обработчик команд на стороне адаптера (см. §5).
5. Напишите тест-кейсы (§6) и обновите `tools-reference.md`.

## 4. Как добавить новый адаптер движка

ForgeMind обрабатывает логику конкретного движка через «адаптеры»; новый движок следует тому же протоколу bridge (4-байтовый префикс длины + JSON-конверт, см. `api-reference.md`):

1. Реализуйте клиент bridge: читайте `%USERPROFILE%\.forgemind\bridge.json` для обнаружения и аутентификации, подключение → handshake → цикл сообщений.
2. Зарегистрируйте обработчики в whitelist по именам команд; все команды выполняются в главном потоке движка (аналог game thread в UE).
3. Реализуйте функции на стороне движка (чтение/запись ассетов, операции с проектом и т.д.) и сопоставьте их с результатами инструментов сервера.
4. Добавьте тест-кейсы и документацию для этого движка.

Первая реализация — адаптер UE `UEProject\ForgeMind_5_0\ForgeMind_5_0\Plugins\ForgeMindForUE\` (плагин модуля Editor, клиент bridge + применитель IR).

## 5. Команды bridge на стороне движка (текущая реализация UE)

- Плагин `ForgeMindForUE` на стороне адаптера содержит клиент bridge; обработчики команд выполняются в game thread.
- Операции на уровне ассетов могут переиспользовать IR-обработчики плагина, избегая дублирования логики редактора.
- Отладка: категория `LogForgeMindBridge` в логах редактора UE; при разрыве соединения — повторное подключение с экспоненциальным backoff.

## 6. Запуск тестов

### Публичные модульные тесты (без редактора)

```powershell
dotnet run --project tests\ForgeMind.PublicTests\ForgeMind.PublicTests.csproj
```

Покрывают round-trip упаковки SPK, мультиверсионный SPK и провайдеров данных сканирования (`EmbeddedSpkTests` / `ScanPackRoundTripTests` / `SpkMultiVersionTests` / `SpkScanDataProviderTests`).

### Интеграционные тесты сервера (требуется редактор UE + пример проекта)

```powershell
# По умолчанию: собирает хост и плагины, делает staging в каталог plugins, запускает хост, загружает плагины и рефлексивно выполняет все ITestCase
ForgeMindServerTest.exe

# Фильтр: по группе + порядку
ForgeMindServerTest.exe [group] [order]          # или --Test [group] [order]
# Пропустить предварительную сборку
ForgeMindServerTest.exe --NoBuild
```

Механизм:

- Предварительная сборка: сначала собирает `ForgeMindServer.csproj`, затем находит проекты плагинов с одноимённым `.manifest.json` под `ForgeMind.*` и собирает их по одному, делая staging в `<входной_каталог>\plugins\<имя_плагина>\`.
- Выполнение: рефлексивное обнаружение `ITestCase`, сортировка по `Group` / `Order`, **fail-fast**; «открыть редактор / закрыть редактор» тоже являются обычными кейсами (`Order=0` открывает, `Order=int.MaxValue` закрывает), сессия общая в группе.
- Кейсы вызывают инструменты напрямую через `ITool.Execute` (минуя протокол MCP); внутри инструменты общаются с UE через bridge.
- Вывод: по завершении формируется JSON-отчёт и читаемое резюме (каталог вывода указывается в результате выполнения).
- Тестовые ассеты: 30+ `Blueprint_*_Tests.cs` в `Task\UE5_0\` (различные домены блюпринтов: переменные / функции / события / материалы / макросы / интерфейсы и т.д.) + `Task\Base\Engine_List_Tests.cs`; `BlueprintTestHelper` инкапсулирует команды bridge, распределение текста и сравнение IR-снимков (для защиты от случайных изменений).

> Примечание: кейсы, связанные с «текстовыми путями (DSL)», зависят от коммерческих DSL-функций; интеграционные тесты публичного среза в основном опираются на команды bridge, как в реальных кейсах в `Task\` среза.

## 7. Авторизация и коммерческие функции (обзор)

- По умолчанию `OpenAuthorizationService` (`ForgeMindServer\Authorization\Open\`): фиксированные возможности сообщества, не анализирует никакой файл лицензии.
- Коммерческая авторизация предоставляется заменой `IAuthorizationService` через ServiceOverride в манифесте плагина (хост применяет `ApplyServiceOverride`). Публичный срез не содержит этот коммерческий плагин, сохраняется только механизм замены (хост не знает понятия «коммерческий», просто заменяет по абстрактному типу).

## 8. Соглашения о коде

- Заголовок файлов содержит SPDX-идентификатор лицензии и объявление копирайта (Apache-2.0).
- Не ссылайтесь на коммерческие модули; новые плагины соблюдают границы среза, определённые в `contributing.md`.
