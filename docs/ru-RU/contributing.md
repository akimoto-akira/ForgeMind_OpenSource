# Руководство по контрибуции в ForgeMind

Спасибо за интерес к ForgeMind. Публичный репозиторий соответствует издательскому срезу OpenSource проекта ForgeMind и содержит только опубликованные проекты с открытым исходным кодом, тесты и примеры проектов. Коммерческие модули (доменные трансляторы DSL, система авторизации и т.д.) не входят в публичный репозиторий: перед контрибуцией уточните разделение областей.

## 1. Структура публичного репозитория

Структура верхнего уровня open source среза (то есть репозитория, который вы клонируете):

```
ForgeMind.sln                          # Решение (содержит ссылки на коммерческие проекты, см. ниже)
OpenSource\                            # Проекты с открытым исходным кодом
  ForgeMindServer\                     # MCP-сервер (хост)
  ForgeMind.OfflineEngineKit\          # Плагин офлайн-инструментов движка (engine/project/launch/build/editor и т.д.)
  ForgeMind.Assets\                    # Плагин чтения ассетов (asset)
  ForgeMind.Knowledge\                 # Плагин поиска knowledge (knowledge)
  ForgeMind.EngineScanner\             # Сканер движков (командная строка)
  ForgeMind.Scan\                      # Упаковка сканирования
  ForgeMind.Scan.Abstractions\         # Абстракция сканирования
  ForgeMind.Scan.Unreal\               # Реализация сканирования UE (DocumentEngine)
  ForgeMind.Speedy\                    # Формат упаковки SPK
UEProject\
  ForgeMind_5_0\                       # Пример проекта UE (совместимость 5.0–5.8)
tests\
  ForgeMind.PublicTests\               # Публичные модульные тесты (SPK / данные сканирования)
  ForgeMindServerTest\                 # Интеграционные тесты сервера (требуется редактор UE)
```

> Примечание: файл решения текущего репозитория разработки (`ForgeMind.sln`) содержит ссылки на проекты Commercial (например, `Commercial\ForgeMindLicenseGenerator`, `Commercial\ForgeMindLicenseServer`); публикуемый продукт **не включает каталог `Commercial/`**, поэтому пользователям OpenSource следует собирать публичные проекты по отдельности (см. §3) и не запускать `dotnet build ForgeMind.sln`.

## 2. Границы OpenSource

- **OpenSource\**: всё открыто (Apache-2.0), основная область контрибуции.
- **UEProject\**: пример проекта открыт, но при экспорте среза исключаются бинарные ассеты `*.uasset` (в Content остаются только текстовые ассеты, например карты, и структура каталогов).
- **tests\**: открыто; контрибуции должны сопровождаться тестами.
- **Commercial отсутствует в публичном репозитории**: доменные трансляторы DSL, коммерческая авторизация и т.д. не встречаются в срезе; код open source не может ссылаться на типы из коммерческих модулей.
- При экспорте автоматически исключаются сборочные и временные каталоги, такие как `bin` / `obj` / `Binaries` / `Intermediate` / `Saved` / `DerivedDataCache`; идентификаторы лицензий в файлах при экспорте единообразно заменяются на Apache-2.0.

## 3. Сборка

```powershell
# Собирайте по отдельности (не собирайте напрямую всё решение, см. выше)
dotnet build OpenSource\ForgeMindServer\ForgeMindServer.csproj
dotnet build OpenSource\ForgeMind.Scan.Abstractions\ForgeMind.Scan.Abstractions.csproj
dotnet build OpenSource\ForgeMind.Scan\ForgeMind.Scan.csproj
dotnet build OpenSource\ForgeMind.Scan.Unreal\ForgeMind.Scan.Unreal.csproj
dotnet build OpenSource\ForgeMind.Speedy\ForgeMind.Speedy.csproj
# Проекты плагинов (после сборки поместите артефакты + одноимённый .manifest.json в каталог plugins хоста)
dotnet build OpenSource\ForgeMind.OfflineEngineKit\ForgeMind.OfflineEngineKit.csproj
dotnet build OpenSource\ForgeMind.Assets\ForgeMind.Assets.csproj
dotnet build OpenSource\ForgeMind.Knowledge\ForgeMind.Knowledge.csproj
dotnet build OpenSource\ForgeMind.EngineScanner\ForgeMind.EngineScanner.csproj
```

Хост загружает плагины из `<каталог_хоста>\plugins\` (переопределяется переменной окружения `FORGEMIND_PLUGINS_DIR`); пакет плагина = основная DLL + одноимённый `.manifest.json` + зависимости (см. `development-guide.md` §3).

## 4. Соглашения о коде

- Все исходные файлы сохраняют в заголовке SPDX-идентификатор лицензии и объявление копирайта (сейчас Apache-2.0).
- Пространства имён организованы по модулям (`ForgeMindServer.*` / `ForgeMind.*`); публичные контракты проходят через абстрактные интерфейсы, такие как `ITool` / `IPlugin`.
- Классы инструментов сервера должны предоставлять полный `Description` и схему параметров (эти тексты напрямую отображаются AI-клиентам).
- Код адаптеров движков следует соглашениям кодирования соответствующего движка (текущая сторона UE: префиксы типов F / U / T, макрос `TEXT()`, ограничения безопасности game thread).
- Новый код не может ссылаться на коммерческие модули и зависеть от них.

## 5. Процесс PR

1. Создайте ветку от `main`, рекомендуемое имя `feat/<описание>` или `fix/<описание>`.
2. Сообщение коммита: `<тип>: <описание одним предложением>`.
3. Самопроверка перед коммитом:
   - собирайте по отдельности по §3, всё должно проходить;
   - если изменение затрагивает команды моста / поведение инструментов, соответствующие группы `ForgeMindServerTest` должны проходить (способ запуска в `development-guide.md` §6);
   - если затрагивает SPK / данные сканирования, должны проходить `ForgeMind.PublicTests`;
   - не добавляйте ссылок на коммерческие модули;
   - синхронно обновите соответствующие страницы в `docs\zh-CN\`.
4. Открывая PR, заполните: содержание изменения, сводку результатов тестов, необходимость ревью конкретных модулей мейнтейнером.
5. Точки ревью мейнтейнера: границы open source, совместимость API, покрытие тестами.

## 6. Требования к тестам

- Изменения команд моста / поведения инструментов / логики адаптеров должны сопровождаться тест-кейсами (добавляйте `*_Tests.cs` в `tests\ForgeMindServerTest\Task\`).
- Интеграционные тесты сервера требуют окружения редактора UE; тесты чистой обработки данных (SPK, сканирование) идут в `tests\ForgeMind.PublicTests\`, без зависимостей от движка.
- Кейсы должны стабильно проходить в порядке по умолчанию (fail-fast, остановка на первой ошибке).

## 7. Контрибуция в документацию

- Документация на китайском находится в `docs\zh-CN\`; содержание должно соответствовать фактам исходного кода; при неуверенности помечайте как «ожидает подтверждения».
- При изменении списка публичных инструментов обновите также `tools-reference.md`.
- Коммерческие функции (синтаксис DSL, механизм авторизации) в документации — только обзор, без внутренних деталей.

## 8. Кодекс поведения

- Уважайте существующие дизайн-решения (протокол моста, контракты инструментов, формат SPK); важные изменения следует сначала обсудить.
- Не очерняйте публично конкурирующие продукты; промо-материалы следуют правилам публичной коммуникации из `promo.md`.
