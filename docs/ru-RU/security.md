# Безопасность ForgeMind

Этот документ описывает дизайн безопасности и рекомендации по использованию публичного среза.

## 1. Границы локальной коммуникации

- **Сервер по умолчанию слушает только loopback**: в режиме HTTP слушает `127.0.0.1:8765`, не выставляется во внешнюю сеть.
- **Мост — это локальный TCP**: между хостом и адаптером движка — локальное TCP-соединение; адаптер должен прочитать `%USERPROFILE%\.forgemind\bridge.json` (хост, порт, учётные данные) для обнаружения и аутентификации перед handshake.
- Не выставляйте порт сервера в публичную сеть; для удалённого использования размещайте в доверенной сети и проксируйте через безопасный канал (например, SSH-туннель).

## 2. Целостность плагинов

- `PluginLoader` хоста выполняет **проверку целостности манифеста** (`PluginIntegrityVerifier`) и проверку подписи (`PluginSigningKeys`) при загрузке плагинов: пакет должен содержать основную DLL + одноимённый `.manifest.json`; при отсутствии или несоответствии отклоняется / пропускается.
- Внедрение инструментов плагинов происходит в процессе хоста; устанавливайте только плагины из доверенных источников (собранные из публичного среза или официальных релизов).

## 3. Модель авторизации

**Раскрываемые механизмы безопасности**:
- `IAuthorizationService`: абстракция точки входа авторизации хоста; реализация по умолчанию — `OpenAuthorizationService` (фиксированные возможности сообщества, не анализирует никакой файл лицензии и не генерирует пробные авторизации).
- Доверенное ServiceOverride: через ServiceOverride в манифесте плагин может заменять сервисы хоста по абстрактному типу (хост не знает понятия «коммерческий», просто заменяет по типу).
- Аутентификация идентичности плагинов и проверка манифеста: `PluginIntegrityVerifier` / `PluginSigningKeys` проверяют манифесты и подписи плагинов, гарантируя загрузку только доверенных плагинов.
- Аутентификация соединения моста: адаптер выполняет обнаружение и handshake учётных данных через `bridge.json`, подтверждая надёжность источника соединения.

**Коммерческая авторизация**: Core предоставляет абстракцию `IAuthorizationService` и доверенный механизм расширения ServiceOverride. Реализация коммерческой авторизации — плагин с закрытым исходным кодом; конкретный протокол авторизации, выпуск, проверка и логика привязки не входят в публичный срез.

## 4. Права инструментов

- Инструменты операций с движком подчиняются `ServerPermissionChecker` (внутри плагинов) и проверяют авторизацию функций перед выполнением.
- Неудачный `Execute` инструментов единообразно возвращает сообщение об ошибке `ToolResult`, без раскрытия внутренних деталей стека.

## 5. Рекомендации по использованию

- Открывайте порт MCP только доверенным клиентам; клиенты обладают возможностью управления движком, что эквивалентно правам локального администратора.
- Обновляйте плагины, хост и пример проекта, чтобы своевременно получать исправления безопасности.
- Не копируйте учётные данные `bridge.json` в ненадёжные процессы на общих машинах.
- При проблемах безопасности сообщайте по каналам издателя, не раскрывая публично детали неисправленных уязвимостей.
