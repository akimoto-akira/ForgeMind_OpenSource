# ForgeMind 보안

본 문서는 공개 슬라이스에서의 보안 설계와 사용 권장 사항을 설명합니다.

## 1. 로컬 통신 경계

- **서버는 기본적으로 루프백만 리슨**: HTTP 모드는 `127.0.0.1:8765`를 리슨하며 외부 네트워크에 노출되지 않습니다.
- **브리지는 로컬 TCP**: 호스트와 엔진 어댑터 사이. 어댑터는 `%USERPROFILE%\.forgemind\bridge.json`(호스트, 포트, 자격 증명 포함)을 읽어 디스커버리와 인증을 완료한 후 핸드셰이크해야 합니다.
- 서버 포트를 공개 인터넷에 노출하지 마세요. 원격 사용이 필요하면 신뢰할 수 있는 네트워크에 두고 안전 채널(SSH 터널 등)로 전달.

## 2. 플러그인 무결성

- 플러그인 로딩 시 호스트 `PluginLoader`는 **매니페스트 무결성 검증**(`PluginIntegrityVerifier`)과 서명 검증(`PluginSigningKeys`)을 수행: 플러그인 패키지는 메인 DLL + 동일 이름 `.manifest.json`이 필요. 누락 또는 불일치 패키지는 거부/건너뜀.
- 플러그인 주입 도구는 호스트 프로세스 내에서 실행. 신뢰할 수 있는 소스(공개 슬라이스에서 빌드 또는 공식 릴리스)의 플러그인만 설치.

## 3. 인가 모델

**공개된 보안 메커니즘**:
- `IAuthorizationService`: 호스트 인가 진입 추상. 기본 구현은 `OpenAuthorizationService`(커뮤니티 고정 기능, 라이선스 파일을 전혀 파싱하지 않으며 평가판 라이선스도 생성하지 않음).
- 신뢰된 ServiceOverride: 플러그인은 매니페스트의 ServiceOverride로 추상 타입에 의해 호스트 서비스를 치환 가능(호스트는 '상용' 개념을 인식하지 않고 타입으로만 치환).
- 플러그인 신원 검증과 매니페스트 검증: `PluginIntegrityVerifier` / `PluginSigningKeys`가 플러그인 매니페스트와 서명을 검증해 신뢰된 플러그인만 로딩 보장.
- 브리지 연결 인증: 어댑터는 `bridge.json`을 통해 로컬 디스커버리와 자격 증명 핸드셰이크를 완료해 연결 출처가 신뢰할 수 있음을 확인.

**상용 라이선스**: Core는 `IAuthorizationService` 추상과 신뢰된 ServiceOverride 확장 메커니즘을 제공합니다. 상용 라이선스 구현은 클로즈드 소스 플러그인이며 구체적인 라이선스 프로토콜, 발급, 검증, 바인딩 로직은 공개 슬라이스에 속하지 않습니다.

## 4. 도구 권한

- 엔진 조작 도구는 `ServerPermissionChecker`(각 플러그인 내)의 제약을 받으며 실행 전 기능 인가를 검사.
- 도구 `Execute` 실패는 통일적으로 `ToolResult` 실패 메시지를 반환하며 내부 스택 세부 사항을 누설하지 않음.

## 5. 사용 권장 사항

- MCP 포트는 신뢰할 수 있는 클라이언트에만 개방. 클라이언트는 엔진 조작 능력을 가지며 로컬 관리자 권한과 동등.
- 플러그인, 호스트, 샘플 프로젝트를 계속 업데이트해 보안 수정을 신속히 받음.
- 공유 머신에서 `bridge.json` 자격 증명을 신뢰할 수 없는 프로세스에 복사하지 마세요.
- 보안 문제는 배포자 채널로 보고. 미수정 취약점 세부 사항은 공개하지 않음.
