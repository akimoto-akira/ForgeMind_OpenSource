# ForgeMind Troubleshooting

Common problems and solutions (based on the real mechanisms of the public slice).

## 1. Build Failures

**Building `ForgeMind.sln` directly reports "Cannot find Commercial\... project"**
Cause: `ForgeMind.sln` contains reference entries to commercial projects (`Commercial\ForgeMindLicenseGenerator`, `Commercial\ForgeMindLicenseServer`), but the commercial directory is not shipped with the open-source slice.
Solution: build each project individually (`contributing.md` §3), do not build the whole sln; or use the publisher's build script.

**The host still does not see the tool after building the plugin**
- Confirm the plugin DLL and same-named `.manifest.json` are placed in the host `plugins\<plugin name>\` (or the directory specified by `FORGEMIND_PLUGINS_DIR`);
- Check the host log to see whether plugin scanning skipped that package (`PluginLoader` only skips a single failed package, without affecting the host);
- Restart the host (the tool table triggers lazy loading on first access).

## 2. Server Startup Problems

**Port already in use**
When `http://127.0.0.1:8765` is already occupied, an `HttpListenerException` is reported.
Solution: change the port with `--port N` or the environment variable `FORGEMIND_PORT`; update the client address accordingly.

**Client cannot connect / tools/list is empty**
- Confirm the server is listening (log `Listening on http://127.0.0.1:<port>/mcp`);
- Confirm the client URL is `http://127.0.0.1:8765/mcp` (HTTP mode);
- Confirm the plugins are loaded (see above).

## 3. Engine / Bridge Connection Problems

**The editor is open, but tools report "engine not connected / bridge unavailable"**
- Confirm the `ForgeMindForUE` plugin is enabled in the project (`UEProject\ForgeMind_5_0\ForgeMind_5_0\Plugins\ForgeMindForUE\`);
- The bridge adapter reads `%USERPROFILE%\.forgemind\bridge.json` for discovery and authentication; connection fails when the file is missing / credentials do not match;
- Check the UE editor log `LogForgeMindBridge`; on disconnect it reconnects with exponential backoff, so wait for reconnection.

**`launch` / `build` stuck**
Long-running tasks run asynchronously; use `get_task_result` to query results, `list_executing_tasks` to view in-progress tasks; `cleanup_tasks` can clean up records.

## 4. Testing Problems

**`ForgeMindServerTest` prebuild fails**
`--NoBuild` skips the prebuild (use when CI has guaranteed fresh artifacts); the default flow builds the host and stages plugins to `<entry>\plugins\`, and exits directly without executing cases on failure.

**Test interrupted by fail-fast**
Integration tests run by Group / Order with fail-fast: it stops at the first failure (within the same group, must-run cases that close the editor are still executed). After fixing, rerun the group with `ForgeMindServerTest.exe [group]`.

**Tests depend on the editor / sample project**
Cases under `Task\UE5_0\` require the UE editor and session; pure data processing cases (SPK / scanning) run in `ForgeMind.PublicTests`, no editor dependency.

## 5. Data / Asset Problems

**`asset` reading fails**
Offline reading of `.uasset` must match the engine version (`UAssetVersions`); parsing may fail when the version does not match. Confirm the engine version is within the tool's supported range.

**`.spk` cannot be loaded**
Check whether it was generated by `ForgeMind.EngineScanner <spkPath>` and not corrupted; SPK includes CRC verification (`Speedy\Internal\Crc32`), and corrupted files are refused to load.

## 6. Other

**How to enable logging**
Server logs are output by `LogManager` (categories include `ForgeMindServerEntry`, `ForgeMindServerHost`, `ForgeMindServerBridgeServer`, etc.); on the bridge side, check the UE editor output log.

**Commercial capability related problems**
For DSL syntax, licensing and License issues, contact the publisher; the OpenSource version does not parse license files and its capabilities are fixed and open (see `security.md`).
