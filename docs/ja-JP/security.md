# ForgeMind セキュリティ

本ドキュメントは公開スライスにおけるセキュリティ設計と使用上の推奨事項を説明します。

## 1. ローカル通信境界

- **サーバーは既定でループバックのみをリッスン**：HTTP モードは `127.0.0.1:8765` をリッスンし、外部ネットワークに露出しません。
- **ブリッジはローカル TCP**：ホストとエンジンアダプタの間。アダプタは `%USERPROFILE%\.forgemind\bridge.json`（ホスト、ポート、資格情報を含む）を読み取ってディスカバリと認証を完了してからハンドシェイクする必要があります。
- サーバーポートを公衆インターネットに露出しない。リモート利用が必要な場合は信頼できるネットワークに置き、安全なチャネル（SSH トンネルなど）で転送。

## 2. プラグイン整合性

- プラグイン読み込み時、ホスト `PluginLoader` は**マニフェスト整合性検証**（`PluginIntegrityVerifier`）と署名検証（`PluginSigningKeys`）を実行：プラグインパッケージにはメイン DLL + 同名 `.manifest.json` が必要。欠落または不一致のパッケージは拒否 / スキップ。
- プラグイン注入のツールはホストプロセス内で実行。信頼できるソース（公開スライスからのビルドまたは公式リリース）のプラグインのみインストール。

## 3. 認可モデル

**公開されているセキュリティメカニズム**：
- `IAuthorizationService`：ホストの認可エントリ抽象。既定実装は `OpenAuthorizationService`（コミュニティ固定機能、ライセンスファイルを一切解析せず、トライアルライセンスも生成しない）。
- 信頼された ServiceOverride：プラグインはマニフェストの ServiceOverride で抽象型によりホストサービスを置換可能（ホストは「商業」概念を認識せず、型でのみ置換）。
- プラグイン身分検証とマニフェスト検証：`PluginIntegrityVerifier` / `PluginSigningKeys` がプラグインマニフェストと署名を検証し、信頼されたプラグインのみ読み込みを保証。
- ブリッジ接続認証：アダプタは `bridge.json` を通じてローカルディスカバリと資格情報ハンドシェイクを完了し、接続元が信頼できることを確認。

**商用ライセンス**：Core は `IAuthorizationService` 抽象と信頼された ServiceOverride 拡張メカニズムを提供します。商用ライセンス実装はクローズドソースプラグインであり、具体的なライセンスプロトコル、発行、検証、バインドロジックは公開スライスに属しません。

## 4. ツール権限

- エンジン操作ツールは `ServerPermissionChecker`（各プラグイン内）の制約を受け、実行前に機能認可をチェック。
- ツール `Execute` の失敗は統一的に `ToolResult` 失敗メッセージを返し、内部スタック詳細を漏らしません。

## 5. 使用上の推奨事項

- MCP ポートは信頼できるクライアントにのみ開放。クライアントはエンジン操作能力を持ち、ローカル管理者権限と同等。
- プラグイン、ホスト、サンプルプロジェクトを更新し続け、セキュリティ修正を迅速に受け取る。
- 共有マシンでは `bridge.json` 資格情報を信頼できないプロセスにコピーしない。
- セキュリティ問題は公開元のチャネルで報告。未修正の脆弱性の詳細は公開しない。
